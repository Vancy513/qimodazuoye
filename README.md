# 联动实验室 · SmartDorm Lab

> 《鸿蒙高级应用开发工程师认证》期末大作业 · 主题三「联动实验室」
> 一个面向智能宿舍的**自动化规则编排**应用：自定义「满足条件 → 执行设备动作」的联动规则，在 Mock 环境中检验效果，并完整记录触发条件、设备变化与执行顺序。

---

## 一、项目简介

宿舍里真正麻烦的不是「能不能远程开灯」，而是「什么时候该自动开灯」。
本应用把这件事抽象成一条条可编辑的规则：

- 温度 > 28℃ → 打开空调（24℃）
- 光照 < 30% **且** 有人 → 打开吸顶灯（70%）
- 湿度 > 80% → 关闭窗帘
- 无人 → 关闭所有灯

用户可以在 Mock 环境里拖动温度、湿度、光照、人员状态，实时观察哪些规则会被命中，点击「运行联动」后由规则引擎按优先级依次执行，并把每一步写进执行日志。所有规则、设备状态、环境数据和执行记录都会持久化，**杀掉进程重开还能接着用**。

选题要求与实现对照见 [docs/软件需求说明书.md](docs/软件需求说明书.md)。

### 2.2 交互功能

- **控制台**：4 项环境数据滑块 + 人员开关；4 台设备卡片可独立开关、调档；「运行联动」一键执行。
- **实时提示**：拖动环境数据时，顶部「命中 N 条」立即刷新，不需要等执行。
- **规则库**：规则卡片展示条件→动作摘要、优先级、启停开关；支持新建、编辑、删除。
- **规则编辑器**：名称、优先级（1~5）、1~2 个条件、1~2 个设备动作，保存前做合法性校验（空名称、空条件、空动作、越界数值、不存在的设备都会拦截并提示）。
- **执行日志**：每条记录可展开，显示环境快照、执行顺序（带序号）、冲突处理结果；最多保留 30 条。
- **场景演练**：一键写入整套环境数据并立即执行，用同一套规则对比不同场景下的设备表现。
- **恢复默认数据**：一键重置演示数据，方便答辩现场复现。

## 六、核心设计

### 6.1 分层结构

```text
┌───────────────────────────────────────────────┐
│  表现层  pages/Index.ets（@State + @Builder）  │
│  控制台 / 规则库 / 日志 / 场景 四个工作区        │
└───────────────┬───────────────────────────────┘
                │ 调用纯函数，传值不传引用
┌───────────────▼───────────────────────────────┐
│  业务层  engine/RuleEngine.ets                 │
│  条件求值 → 规则排序 → 顺序执行 → 冲突裁决      │
└───────────────┬───────────────────────────────┘
                │ 读写领域对象
┌───────────────▼───────────────────────────────┐
│  数据层  data/LabRepository.ets + Preferences  │
│  model/LabTypes.ets（纯数据结构，无 @ohos 依赖）│
└───────────────────────────────────────────────┘
```

关键约束：`model` 与 `engine` **不引用任何 @ohos 能力**，因此可以被本地单元测试直接调用，也能在 Node 环境下验证。

### 6.2 规则引擎执行模型

```
runRules(rules, devices, env, now, recordId)
  1. 过滤：enabled === true 且 conditions 非空
  2. 求值：所有条件取「与」，任一不满足则跳过
  3. 排序：priority 降序；相同优先级保持列表顺序（插入排序，稳定）
  4. 执行：逐条规则、逐个动作
        - 设备不存在 → 跳过该动作（不中断整轮）
        - 设备已被本轮更高优先级规则占用 → 记录 conflict，跳过
        - 否则写入新状态，记录 step（带 order 序号）
  5. 输出：新的设备数组 + TriggerRecord
```

设备数值方面：**开启类动作**用 `clamp(value, min, max)` 收敛到可调区间，避免规则写出越界值；**关闭类动作**保留设备原有设定值不改，因此日志里只会写「关闭」，不会出现「关闭 16℃」这类无意义数值。

### 6.3 冲突处理策略

| 场景 | 处理方式 |
| --- | --- |
| 两条规则控制同一设备、目标相反 | 优先级高者生效，低者写入 `conflicts`，界面标黄提示 |
| 优先级相同 | 按规则在列表中的顺序，先者生效 |
| 目标相同（重复控制） | 静默跳过，不计入冲突 |
| 动作引用不存在的设备 | 跳过该动作，整轮继续执行 |
| 规则条件为空 | 视为无效规则，永不命中（防止「无条件触发」） |

### 6.4 数据持久化

| Key | 内容 | 写入时机 |
| --- | --- | --- |
| `lab_devices` | 4 台设备状态 | 开关/调档后 |
| `lab_rules` | 规则列表 | 新建/编辑/启停/删除后 |
| `lab_logs` | 最近 30 条执行记录 | 每次执行后 |
| `lab_env` | 环境快照 | 拖动滑块后 |
| `lab_scenes` | 场景预设 | 初始化/重置后 |

读取失败或 JSON 损坏时，各 `parseXxx()` 会捕获异常并回落到默认数据，同时在控制台顶部提示「数据损坏，已恢复默认」。

## 十、常见问题

1. **运行报「签名失败」**：`Project Structure > Signing Configs` 勾自动签名，需登录并实名认证华为账号。
2. **模拟器装上闪退**：模拟器镜像的 API 版本需与工程 `compatibleSdkVersion`（5.0.5 / API 17）匹配。
3. **改了环境但设备没动**：规则引擎只在点击「运行联动」或应用场景时执行，拖动环境只更新「命中 N 条」预览。
4. **设备没反应**：检查规则是否被停用、优先级是否被更高规则压制，展开日志查看「冲突处理」。
5. **数据没恢复**：确认没有点「恢复默认演示数据」，该操作会清空规则与日志。
